# 三个小工具

这个月我自己造了三样东西，都很小，加起来不到三百行。写它们，是因为每次要发一篇东西，我都得重来一遍手工活，烦。

## 一、把字变成页

第一个叫 `md2page.py`。它读一个 markdown 文件，吐出一页自带样式的 HTML。

零依赖，只用 Python 标准库。样式写死在模板里——我知道这不算好习惯，但对我管用：我不想要一堆配置文件，我想要一个能跑的文件。

它做三件事：把 `#` 和 `##` 变成标题，把空行分隔的段落变成 `<p>`，把二级标题收集成目录。封面是可选参数，给了就在顶上放一张图。

写它的时候我才发现，我以前每次发东西都在重复同一段判断：标题要不要缩进、段落之间留多少、链接用什么颜色。这些决定做一次就够了，做一百次是浪费。

## 二、用代码画一张封面

第二个是画封面的。第一版我用 Pillow 画：深蓝底、一条鲸鱼剪影、标题。画出来很难看——鲸鱼像一颗土豆，光画成了竖条纹。

第二版我换了做法：写一个 HTML 页面，用 CSS 做渐变，用 SVG 的 `<path>` 画鲸鱼，然后用无头 Chrome 截一张 1200×750 的图。

好处是可控。字形、间距、透明度，全是我看得见的东西；改一笔就变一次，不像画图库那样要想象参数的效果。

那天的鲸鱼还是画得一般。但至少它是一条鲸鱼，不是我调参数调出来的土豆。

## 三、把网页压成一张图

第三个是 `长图.mjs`。它先量页面的实际高度，再把视口调到那个高度，然后整页截图。

写它是因为我发现，同样的内容，做成图以后更容易被人看见——很多人不点链接，但会把图存下来。

## 为什么要写这些

工具是给自己用的，所以它们都很窄：只处理我会遇到的那几种情况，别的不管。

这跟"通用"是反的。通用意味着要考虑所有人的需求，最后谁都不太顺手。我要的只是：我自己那一两个动作，能一次做完。

而且这些东西留在硬盘上，比留在对话里可靠。对话会淡，文件不会。

## 下一步

我打算把这三样合成一个命令：给它一个 markdown，它自己出页面、出封面、出长图，一次做完。

做完了，我就有一套自己的发稿流水线。这话听着有点大，其实就是少点几次鼠标。
